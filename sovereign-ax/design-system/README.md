# 소버린 AX 디자인 시스템

이 폴더는 화면 디자인과 앱 UI 구현의 기준이다. 값의 원본은 `tokens.json`이고, 데이터를 어떻게 보여 줄지는 `data-hierarchy.md`가 정한다. 방향은 `direction-review.html`의 A안("서류와 도장") 구조에 파랑 계열 강조색 하나를 쓰고 색 사용을 최소화하는 것으로 정했다(2026-10-30). v1.2(2026-11-02)는 같은 방향 위에서 면·선·굵기·간격을 다듬었다.

미리보기(`preview.html`)는 아티팩트가 `tokens.json`에서 만드는 CSS 변수 위에서 렌더된다. 저장소의 `preview.html`만 열면 색과 서체가 빠진다. 전체 모습은 `direction-review.html`로 본다. 토큰이나 컴포넌트를 바꾸면 아티팩트와 이 폴더를 함께 고친다.

소버린 AX는 자영업자·소규모 법인이 세금계산서와 홈택스 증명서 발급을 맡기는 Windows 데스크톱 에이전트다. 화면은 서류처럼 정확하고 조용해야 한다. 바탕과 글자는 무채색이고, 색은 두 가지 뜻에만 쓴다. 어떤 값이 얼마나 중요한지는 색이 아니라 **데이터 위계**([data-hierarchy.md](data-hierarchy.md)) 단계가 정한다.

## v3.0 확정 기준 (2026-11-24, 가장 먼저 읽는다)

대표 지시(2026-11-24): "컴포넌트화해야 하는 것과 디자인 시스템으로 고정해야 하는 것이 안 되어서 자꾸 흔들린다. 버튼 위치, 카드 테두리 등. 완전히 확정하고 흔들리지 않게 코드와 캔버스로 정리한다." 이 절은 그 확정판이다. 아래 v2.x 규칙과 부딪히면 이 절이 이긴다. 폰(`LAF-labs/taxoff-mobile`)도 같은 규칙을 따르고 크기만 다르다(폰 `docs/design.md`).

- 기준 캔버스는 하나다: [택스오프 화면 기준판](https://claude.ai/artifact/G6SV8Bi6ZS5gyiZDBvgfEa). 규칙, PC와 폰 부품, 화면을 담고 계속 판을 올린다. 기준판에는 승인된 최신 모습만 둔다(대표 2026-11-24 "기준판은 최신 업데이트만 해야 함"). 시안과 지금, 바꾼 뒤 비교는 따로 캔버스에 그려 승인받고, 승인된 모습만 기준판으로 옮긴다. 예전 캔버스는 기록으로 둔다.
- 새 화면은 이 절의 부품만 써서 만든다. 부품에 없는 모양이 필요하면 화면에서 따로 그리지 않고 부품을 먼저 더한다(캔버스에 그리고 승인받은 뒤).
- `(승인 대기)`가 붙은 줄은 이 스레드가 정한 값이고 기준 캔버스 승인 뒤 확정된다. 나머지는 대표가 이미 정한 것이다.

### 규칙

1. **카드.** `surface-tint` 채움 면 하나, 모서리 `radius-lg`, 안쪽 16, 요소 사이 12. 어떤 상태에서도 테두리, 안쪽 선, 색 띠, 그림자를 더하지 않는다(대표 2026-11-24 "카드 테두리는 지저분하니 모두 없앤다"). 카드 안에 카드를 넣지 않는다. v2.0의 "내 차례, 확인 필요 카드의 1px 안쪽 선"은 없앤다.
2. **카드 종류는 제목 앞 아이콘.** 18px 선 아이콘 하나, 기본 색 `ink-2`. 문서(발급, 발급한 계산서, 증명서), 연필(고치기), 동그라미 X(취소), 세모 느낌표(사장님 확인이 필요한 일), 동그라미 체크(발급 완료), 동그라미 느낌표(발급 실패, 대표 2026-11-24 "완료된 발급과 실패한 발급도 아이콘 필요"). 완료와 실패 아이콘에는 색을 쓰지 않는다. 취소 아이콘은 늘 `danger`(라이트 `#D92D20`, 다크 `#FF6B5E`)다. 승인을 기다리는 카드는 같은 아이콘을 `accent`로, 확인이 필요한 카드는 `attention`으로 칠한다. `danger`는 취소 아이콘에만 쓰고 글자, 면, 단추에는 쓰지 않는다.
3. **카드 머리 줄.** 아이콘, 제목, 그리고 진행 상태 칩(준비 중, 발급 중, 확인 중)뿐이다. 아이콘 색이 이미 말하는 상태(승인 대기, 확인 필요)는 칩으로 되풀이하지 않는다(승인 대기). 머리 줄에 단추를 두지 않는다. [중지]도 단추 줄에 둔다. 예외는 한 줄 카드(`sx-card.is-line`)다. 아이콘, 한 문장, 진행 칩, 그리고 오른쪽 끝 글자 단추(`sx-btn-text`) 하나까지 한 줄에 둔다. 진행은 카드 바닥에 겹친 막대(`sx-progress`)라 상태가 바뀌어도 높이가 54로 같다(대표 2026-11-28 "높이가 제각각이면 안 되지. 카드 안에 있는 버튼이면 텍스트버튼으로, 버튼 영역 없이 글자만").
14. **글자 단추.** `sx-btn-text`는 칸, 채움, 높이 없이 글자만이다. 기본 `ink-2`, 주 동작은 `is-main`(`ink`, 600). 카드 안에 딸린 작은 동작(닫기, 업데이트)에 쓴다. 단추 줄(`sx-actions`)의 단추는 그대로 알약이다.
4. **값.** 라벨 왼쪽(`ink-3`), 값 오른쪽 정렬 고정폭 숫자. 금액도 본문 크기이고 합계만 600이다. 승인 카드의 큰 합계 글자(24)는 쓰지 않고 합계를 값 묶음의 마지막 줄에 둔다(승인 대기).
5. **단추 줄.** 카드, 모달, 시트 어디서나 가장 중요한 단추가 맨 앞이다(대표 2026-11-24). 채운 단추(`ink`, 승인은 `accent`)는 한 줄에 하나다. PC는 카드와 모달 모두 단추 줄을 오른쪽에 붙인다(대표 2026-11-24 캔버스 댓글 "PC에서 모든 버튼을 오른쪽으로". 같은 날 앞서 정한 "왼쪽부터"를 바꿨다). 단추 옆 안내 글은 줄 왼쪽에 둔다. 정렬은 공용 `sx-actions` 한 곳에서만 정하고 화면에서 따로 밀지 않는다. 간격은 8 하나다(지금은 4, 6, 8이 섞여 있다). 폰 단추는 줄을 꽉 채운다. 하나면 가득, 둘이면 반씩, 셋이면 한 줄에 하나씩 세 줄로 두고 주 단추가 맨 위다(대표 2026-11-24 "셋이면 줄마다 둘/하나 혹은 하나하나하나"). 카드나 목록 항목에 딸린 작은 단추는 PC와 같이 오른쪽에 붙인다(대표 2026-11-24 캔버스 댓글 "이것들도 다 오른쪽으로"). 시트에서 그 밖의 동작은 시트 안 목록 줄로 둔다(대표 2026-11-24 "두 줄이면 다른 UI가 필요, 덜렁 떨어져 있으면 안 됨. 토스 참고"). 목록 줄 하나에 딸린 동작([끊기] 등)은 그 줄 끝에 둔다.
6. **PC 모달.** `scrim` 위 가운데 `surface-overlay` 면, 모서리 `radius-xl`, 안쪽 24, `shadow-overlay`. 머리 줄은 제목(15/600)과 오른쪽 닫기 단추(32 원)다. 머리 줄 높이는 제목 글줄이고, 닫기 단추가 줄을 키워 제목이 아래로 밀리지 않게 한다. 여백은 상자가 아니라 보이는 글자 기준으로 맞춘다. 제목 글자 위와 왼쪽이 같은 24로 보여야 한다(대표 2026-11-24). 닫기 단추, 바깥 누르기, Esc 세 가지로 모두 닫힌다(K-75). 폭은 400(확인), 560(입력), 920(목록) 셋 중 하나다(승인 대기). 단추 줄은 오른쪽 아래, 높이 40. 새 창을 띄우지 않는다.
7. **폰 시트.** 바닥에서 올라오는 `surface-overlay` 면, 위 모서리 22, 손잡이, 머리 줄 오른쪽 닫기 단추. 닫기 단추, 바깥 누르기, 아래로 끌기로 닫힌다. 주 단추는 시트 바닥에 두고 키보드가 뜨면 시트째 올라간다(TDS 바텀시트, 폰 `docs/design.md` "단추 자리"). 바닥 단추는 하나나 둘이고 한 줄이다. 그 밖의 동작(고치기, 발급 취소)은 시트 안 목록 줄로 둔다. 확인도 같은 시트로 묻고 단추 둘을 반씩 나란히 둔다.
8. **표.** 줄은 `line` 선 하나로 나눈다. 값은 모든 줄에서 테두리 없는 입력 칸이다. 누른 입력 칸은 표 칸, 금액 칸, 입력창 어디서나 같다. 파란 테두리를 쓰지 않고, `surface-overlay` 면에 옅은 회색 선 1px(`ink-4`)과 뒤 그림자, 커서로 알린다(대표 2026-11-24 "파란 테두리는 너무 튐", "모든 인풋에서. 입력창 뒤로 그림자를 주고 가볍게 회색 테두리"). 한 줄 안의 체크 상자, 점, 글자는 세로 가운데를 맞춘다. 금액 열은 오른쪽 정렬 고정폭 숫자, 폭 124. 확인할 건은 `attention` 점과 짧은 이유를 이름 옆에 붙인다.
9. **금액 고치기.** 항목마다 두 줄이다. 윗줄에 이름과 "기존 금액"(`ink-3`), 아랫줄에 카드 폭을 다 쓰는 고칠 금액 칸(높이 44, `canvas` 면, 600). 공급가액, 부가세, 합계는 하나를 고치면 나머지가 따라 바뀐다. 줄 긋기, 옆으로 나란한 칸을 쓰지 않는다.
10. **색과 상태.** `accent`는 내 차례와 승인, `attention`은 확인 필요, `danger`는 취소 아이콘. 상태는 점과 글자다. 완료와 실패에는 색을 쓰지 않는다. 주의 면(`attention-soft`)은 한 카드에 하나다.
11. **글.** 가운데점을 쓰지 않는다. 회색 보조 글씨와 설명 줄을 넣지 않는다. 단추 글은 두세 낱말. 내부 상태값과 오류 코드를 내지 않는다(아래 "문구" 절).
12. **영역.** 성격이 다른 영역은 면이나 머리카락 선 하나로 나눈다. 한 화면은 한 가지 방법만 쓴다. 모달과 시트 위의 채움 면은 다크에서 한 단계 밝은 `surface-sunken`을 쓴다(면과 바탕이 같은 값이라 묻힌다).
13. **폰 아래 탭바.** 떠 있는 탭바다. 평소에는 아이콘 아래 작은 글자를 두고, 줄어들면 아이콘만 남긴다(대표 2026-11-24). 스크롤하면 폭은 그대로 두고 높이만 줄며, 입력창과 맨 아래로 단추가 함께 내려간다(taxoff-mobile #68).

### 근거

- 카드 테두리, 아이콘 넷, 취소 빨강, 중요한 단추 먼저, PC 단추 오른쪽, 표 입력 칸, 금액 두 줄, 탭바: 대표 지시 2026-11-24(작업 노트 2절, ADR-058 결정 5, ADR-059 캔버스).
- 모달이 닫히는 세 가지 길: 대표 지적 2026-11-24(K-75).
- 시트 바닥 단추와 키보드: 토스 디자인 시스템 바텀시트(https://tossmini-docs.toss.im/tds-mobile/components/bottom-sheet/, K-67).
- 폰 단추 한 줄: TDS Mobile `BottomCTA`는 Single과 Double 둘뿐이다. Double은 좌우 같은 폭(실측 283과 284, 간격 8, 높이 56)이고 세 개나 두 줄 꼴이 없다. `BottomSheet.DoubleCTA`도 좌우로 나뉜다. 그 밖의 동작은 `topAccessory`, `Menu`, `ListRow`로 둔다(2026-11-24 문서 화면 실측). 토스는 주 단추가 오른쪽이지만 순서는 대표 지시대로 주 단추가 앞이다.
- 큰 합계를 없앤 것: v2.0 "금액도 14, 중요한 값은 `ink`와 600으로만". 승인 카드만 24로 남아 규칙이 둘이었다.
- 상태 칩을 줄인 것: 승인된 수정세금계산서 캔버스(ADR-058)의 승인 카드가 아이콘 색만으로 알린다. "화면 글은 최소한으로"(대표 2026-11-23).

### 코드로 지키는 법

- PC 부품의 모양은 `components/bundle.css`의 `sx-*` 클래스 하나씩이다: `sx-card`(`is-line` 한 줄 카드), `sx-card-hd`(아이콘과 제목), `sx-kv`, `sx-actions`, `sx-btn`(`-primary`, `-approve`, `-quiet`, `-text`, `-lg`), `sx-note`, `sx-replies`, `sx-amt`, `sx-modal`(`is-md`, `is-lg`), `sx-table`. 화면 파일(`static/shell/shell-*.js`)은 모달과 단추 줄을 직접 조립하지 않고 `static/shell/shell-ui.js`의 `card()`, `actions()`, `modal()`을 부른다. `actions(주요, ...나머지)`처럼 순서가 인자 자리로 정해져 뒤집어 쓸 수 없다.
- 폰 부품은 `src/ui/`에 있다: `Card`(종류 아이콘), `Actions`, `Sheet`, `ConfirmSheet`, `Button`, `Group`, `Row`, `Field`. 화면(`src/screens/`)에서 `Modal`, 딤, 테두리, 색 값, 글자 크기를 직접 쓰지 않는다.

## v2.0 기준 (2026-11-14, v3.0 다음에 읽는다)

대표 지시는 "디자인을 갈아엎자. Meta Muse처럼 정말 미니멀하게. 중요한 걸 큰 글씨로 표현하려 하지 말고"였다. 이어서 "보이는 걸 따라 하지 말고 어떤 입력에 어떤 UI를 어떤 크기로 주는지까지 구조를 고쳐라"라고 했다. 아래 규칙이 이 문서의 v1.2 규칙보다 우선한다. 색의 두 가지 뜻(accent = 차례·승인, attention = 확인 필요)과 승인 카드 규칙은 그대로다.

- **면.** 선 대신 면으로 나눈다.
  - 바탕은 `canvas` 하나다(`surface`도 같은 값).
  - 카드·말풍선·입력창·보조 단추는 `surface-tint` 채움이다.
  - 테두리는 포커스, 내 차례·확인 필요 카드의 1px 안쪽 선, 입력 칸의 안쪽 선에만 쓴다.

- **글자.**

  - 입력창은 48이다. 알약 어디를 눌러도 글자 칸으로 간다.
  - 레일은 폭 76이다. 항목은 아이콘 22와 짧은 이름이고, 선택 표시는 아이콘 뒤 44×32 알약만이다. 한 칸은 68이고, 묶음은 세로 가운데에 두고 설정은 맨 아래에 둔다(Muse: 폭 78·간격 56).
  - 목록 줄과 메뉴 줄은 36 이상이다.

- **단추의 무게.**
  - 한 카드의 주요 단추는 하나다(`ink` 채움 알약).
  - 같은 값을 고치는 단추들은 둘째 줄의 조용한 단추로 묶는다.
  - 카드 안 보조 단추는 `canvas` 채움이다.
  - 파랑 채움은 승인 카드에만 쓴다.
- **상태.** 칩은 바탕 없이 점 + 글자다. 색은 accent·attention뿐이다.
- **답 후보.** 앱이 물을 때 선택지는 테두리 없는 전폭 면 줄(`sx-replies`/`sx-reply`)로 준다(Muse 확인 UI). 기본은 `surface-tint` 면(카드 안에서는 `canvas` 면), hover는 한 단계 진한 `surface-sunken`이다. 고른 줄은 `accent-soft` 면 + 600 + accent 체크로 굳고 나머지는 흐려진다(고른 값은 내가 정한 것이라 accent 계열을 쓴다). 포커스는 `focus-ring` 2px이다. 점선은 쓰지 않는다(2026-11-16: 초안·미완성처럼 읽힌다). 점선은 파일을 끌어 놓는 칸에만 남긴다. 같은 일에 칩·단추·select를 섞지 않는다. 판정 근거는 `muse-review.md`에 있다.
- **값은 글자, 누르면 칸.** 작성 카드처럼 확인하는 화면에서 값은 글자로 보인다. 누르면 그 자리에서 칸이 된다(`sx-val-btn`). 둘 중 하나를 고르는 값은 두 칸 전환(`sx-seg`)이다.

  - 이번 달 할 일은 대화 맨 위 한 줄이다. 누르면 패널에 목록이 열린다. 대화를 가리는 판을 두지 않는다.
  - 실행 중 카드는 머리 한 줄(제목 · 칩 · 조용한 [중지]) + 지금 하는 일 한 문장 + 진행 막대다(v2.1). 사람 차례·확인 필요일 때만 할 일 한 줄과 주요 단추 하나를 붙인다. 금액·단계·값은 패널에만 있다. 핸드오프 띠는 카드가 화면 밖일 때만 뜬다.
- **주의·안내 면(`sx-note`).** 2026-11-16 온보딩 인증서 카드 지적에서 더했다.
  - 한 카드·패널에 주의 면(`is-attention`)은 하나다. 문장이 여럿이면 한 면 안의 줄로 모은다(`noteGroup`). 원인이 이어지면(보안 프로그램 없음 → 인증서도 못 읽음) 먼저 풀 것 하나만 보이고, 풀리면 다음 것을 보인다.
  - 모양은 아이콘 · 제목(13/600) · 본문(13) · 단추 줄이다. 아이콘은 주의면 경고, 안내면 정보다.
  - 사람이 할 일이 있으면 그 단추가 면 안에 있다. 단추 없이 "옮긴 뒤 다시 열어 주세요"처럼 말만 하는 막다른 안내는 두지 않는다([다시 찾기]처럼 그 자리에서 할 단추를 준다).
  - 면 위 단추는 할 일 하나만 주 단추이고, 나머지는 채움 없는 글자 단추다. 어두운 채움 알약은 다크에서 주의 면에 묻힌다.
- **보이지 않는 것.** 설치 주소·파일 경로·오류 코드·내부 이름 원문은 화면 글에 쓰지 않는다. 주소는 단추가 열고, 코드는 사람 말 표로 바꾸고, 표에 없으면 일반 문장을 쓴다.
- **문구 길이.** 안내 본문은 두 줄 안이다. 같은 말을 제목과 본문에 되풀이하지 않는다.
- **창 크롬.** macOS는 OS 제목줄을 숨기고 앱 제목줄(44) 하나로 합친다. 실행 중이 아닐 때 누를 수 없는 단추([홈택스 화면])는 보이지 않는다.

## 원칙

- 색은 두 가지 뜻만 가진다. `accent`(파랑)는 사용자의 차례와 승인, `attention`(황토)은 확인이 필요함이다. 그 밖의 모든 것은 `ink`·`surface` 계열 무채색으로 만든다.
- 값을 강조하려고 색이나 굵기를 바꾸지 않는다. 데이터 위계 D1~D6 중 맞는 단계의 스타일을 고른다.
- 구분은 선(`line`)으로 한다. 그림자(`shadow-overlay`)는 떠 있는 것에만 쓴다. 입력창만 `shadow-raised`로 살짝 뜬다.
- 되돌릴 수 없는 승인은 대화 열 아래 승인 카드(PC)와 모바일 승인 시트의 승인 버튼으로만 받는다. 승인 카드(components/ApprovalCard)는 main이 대화창과 따로 그리는 스크립트 없는 신뢰 영역이고, 렌더러의 대화 카드에는 승인 버튼을 두지 않는다. 별도 승인 창은 없다(ADR-020, ADR-021 결정 7).
- 홈은 대화 하나다. 숫자 타일 대시보드, 마스코트, 그라데이션, 이모지를 쓰지 않는다.
- 더 조용하고, 더 적게, 더 분명하게(v1.2). 면은 네 단(`canvas`·`surface`·`surface-tint`·`surface-overlay`)으로 끝내고, 테두리는 필요한 곳에만, 굵기는 400·500·600 셋으로, 움직임은 상태가 바뀔 때만 쓴다.

## 색

- 바탕은 `canvas`, 카드·작업 패널·레일·제목줄·입력창은 `surface`, 선택된 레일 항목·행 hover·무채 상태 칩·검색 칸은 `surface-tint`, 누름 상태와 서식 표의 라벨 칸은 `surface-sunken`, 명령 팔레트·메뉴·모달·토스트와 사용자 말풍선은 `surface-overlay`(말풍선은 그림자 없음). 모달 뒤는 `scrim`.
- 글자는 네 단계다. 값과 본문은 `ink`, 보조 문장·식별 번호·추정 값·무채 칩은 `ink-2`, 라벨·출처·빈 값 "—"·정정으로 접힌 줄은 `ink-3`, 비활성만 `ink-4`. 읽어야 하는 글자에는 `ink-4`를 쓰지 않는다(대비 2.4:1, PC 점검 11-20 F07).
- 카드 테두리와 서식 표의 선, 작은 보조 버튼(복사·빠른 실행 칩·필터)의 테두리는 `line`, 카드 안의 보조 구분선은 `line-soft`, 입력 칸·주요/보조 버튼·선택지의 테두리는 `line-strong`(3:1 이상). 빈 입력 칸은 테두리가 유일한 식별 수단이라 반드시 `line-strong`이다(WCAG 2.2 1.4.11).
- `accent`는 내 차례 칩, 승인 대기 칩, 실행 단계의 현재 점, 승인 버튼(승인 카드의 무장된 [승인하고 발급]), 승인 카드 테두리, 승인 도장, 포커스 링(`focus-ring`)에만 쓴다. 링크, 선택된 항목, 일반 주요 버튼(`sx-btn-primary`, `ink`로 채움)에는 쓰지 않는다. 한 화면에 파랑으로 채운 면은 하나까지다. `accent-strong`은 파랑 버튼의 hover·누름에만 쓴다(승인 카드에는 hover가 없다).
- `accent-soft`는 내 차례 칩, 차례 안내 줄, 무장 전 [승인하고 발급]의 바탕이다. 그 위 글자는 `ink` 또는 `accent`.
- `attention`은 확인 필요, 만료 임박(D-7 이하), 휴·폐업 경고, 입력 형식 오류, 되읽기 불일치, InDoubt 증언 카드에 쓴다. 바탕이 필요하면 `attention-soft`.
- 완료는 색으로 표시하지 않는다. `ink` 글자와 체크 표시다. 실패와 차단에도 빨강이 없다. `ink` 테두리 칩과 원인 문구로 보여 준다.
- 모든 글자 토큰은 `surface`·`canvas`·`surface-tint` 위에서 두 테마 모두 4.5:1 이상이다(`ink-4` 제외). 토큰 설명에 실제 대비 값이 있다.

## 서체

- 본문과 UI는 `font-sans`(IBM Plex Sans KR), 식별 번호는 `font-mono`(IBM Plex Mono), 서류 이름은 `font-serif`(Noto Serif KR)로 `doc-name`에만 쓴다. 세 서체 모두 Google Fonts에서 불러오고, 앱에는 OFL 파일로 넣는다.
- 굵기는 400(본문·값)·500(라벨·버튼·칩)·600(제목·D1·주요 버튼) 셋이 기본이다. 700은 서류 이름과 승인 카드의 동작 글자에만 쓴다. 한글 라벨에는 자간을 넣지 않는다.
- 보안카드 등록은 앱과 같은 서체를 쓰고 번호 칸만 `font-mono`다(SecretField). 창은 대화창 안 모달이 아니라 main이 띄우는 OS 테두리 창("금고 · …" 제목)이다(ADR-025·026).
- 승인 카드는 시스템 서체(`font-system`)만 쓴다(ADR-021의 CSP). 값은 `approve-body` 14/22, 합계 24/30 600, 동작 글자 16 700이다(토큰 묶음 이름 "승인 바"는 코드가 읽어서 그대로 둔다).
- 수치에는 고정폭 숫자(`font-variant-numeric: tabular-nums`)를 쓴다. `figure-lg`·`figure`·`value`에 이미 들어 있다.
- 가장 작은 글자는 12px(`label`, `meta`)이다. 한글 본문 행간은 1.6이다(`body` 15/24). 화면 제목(`title-screen`)은 18/26이다.

## 간격과 배치

- 간격은 4px 단위(`space-1`~`space-7`)다. 카드 안쪽 `space-4`, 카드 안 요소 사이 `space-3`, 메시지 사이 `space-4`, 대화 좌우 `space-5`. 한 줄 안의 미세 간격만 `space-0`(2px)이다. 14·18px 같은 반 칸 값은 쓰지 않는다.
- PC 메인은 `titlebar-height` 제목줄 아래에 `rail-width` 레일, 가운데 대화, `panel-width` 작업 패널을 둔다. 대화 콘텐츠는 `chat-max`에서 멈추고, 남는 폭은 작업 패널이 쓴다. 승인 카드의 자리는 이 치수와 앱 상수로만 정하고, 높이는 서류 종류별 줄 수로 main이 정한다(ADR-021 결정 7). v1.2에서 치수는 바꾸지 않았다.
- 모서리는 버튼·입력 칸·선택지 `radius-md`(8), 카드·목록 표 `radius-lg`(12), 입력창·떠 있는 창·사용자 말풍선 `radius-xl`(16), 칩·보내기 버튼 `radius-full`. 서식 칸과 작은 복사 버튼은 `radius-sm`(6). 승인 카드는 불투명한 사각형 뷰 안에 `radius-lg` 카드 면을 그리고, 판정 영역은 두 버튼의 사각형뿐이다. 모든 것을 크게 둥글리지 않는다.
- 조작 높이는 `control-height-sm`(28, 빠른 실행 칩·필터·프로필 전환), `control-height`(32, 버튼·입력 칸), `control-height-lg`(40, 모바일 시트)다.
- 라벨·값 목록의 라벨 칸은 `field-label-width`로 맞춘다.
- 스크롤바는 평소 보이지 않는다. PC에서는 마우스가 스크롤 영역 위에 있거나 스크롤하는 동안만 `line-strong` 얇은 막대로 보이고, 멈추면 다시 투명해진다(앱이 스크롤 뒤 0.8초 동안 `is-scrolling`을 붙인다). 모바일은 OS가 스크롤할 때만 띄우는 표시를 그대로 쓴다.
- 좌우 스크롤은 만들지 않는다. 넘치는 칩·버튼 줄은 줄바꿈하고, 표는 열을 줄이거나 값을 줄바꿈한다. 예외는 문서를 확대해 볼 때뿐이다(특히 모바일).

## 상태

작업 상태는 StatusChip 하나로 보여 준다. 열한 가지이며 강조색이 붙는 것은 셋뿐이다. 무채 칩은 테두리 없이 `surface-tint` 바탕이다.

- 내 차례(`is-turn`)·승인 대기(`is-waiting`): `accent`.
- 확인 필요(`is-attention`): `attention`.
- 작성 중·준비 중·발급 중·확인 중·처리 대기: 기본(무채색). 확인 중은 응답이 끊겨 앱이 발급목록을 다시 조회하는 상태다.
- 완료(`is-done`): `ink` + 체크. 중지됨(`is-stopped`): `ink-3`. 실패(`is-fail`): `ink` 테두리.
- 조작의 hover는 `surface-tint`, 누름은 `surface-sunken`이다. 주요 버튼의 hover는 `ink-2`, 승인 버튼의 hover는 `accent-strong`이다.

## 움직임

움직임은 상태가 바뀌었음을 알리는 데만 쓴다. hover·누름의 색 변화 `motion-fast`(120ms), 상태 칩 변화 `motion-base`(160ms), 작업 패널 열림 `motion-slow`(220ms), 곡선은 `ease-out`. 진행 중은 StepList 현재 점이 `motion-pulse`(2.4초) 주기로 숨 쉬듯 흐려졌다 돌아오는 것으로만 보여 준다. 튀는 효과, 회전 아이콘, 등장 애니메이션을 쓰지 않는다. 승인 카드에는 애니메이션이 없다(정적 페이지 교체, ADR-021). 동작 줄이기 설정이면 모두 끈다.

## 포커스

키보드 포커스는 `focus-ring` 2px 실선, 간격 2px이다. 테두리가 있는 입력 칸은 링 대신 테두리 색을 `ink-2`로 바꾼다. 승인 카드의 기본 포커스는 [중지]이고 링이 처음부터 보인다. 키보드로는 승인되지 않는다(Enter·Space·조합키 모두, ADR-021 결정 7).

## 아이콘

1.5px 선 아이콘을 레일 22px, 본문 16px로 쓴다. 색은 주변 글자 색을 따른다. 채운 아이콘과 이모지는 쓰지 않는다. 로고는 아직 없다. 로고 자리에는 이름을 `title-card`로 쓴다.

## 테마

라이트와 다크는 같은 토큰 이름을 쓴다. 기본값은 시스템 설정을 따른다. 다크에서는 위로 뜰수록 밝다(`canvas` → `surface` → `surface-tint` → `surface-overlay`). 라이트에서는 `canvas`와 `surface`의 차이를 작게 두어 카드가 떠 보이지 않게 한다. 다크의 `accent`는 밝은 파랑이므로 그 위 글자는 `on-accent`(어두운 남색)다. 두 테마를 함께 설계하고 한쪽에서 다른 쪽을 만들어 내지 않는다.

## 문구

짧은 해요체로, 일어난 일과 사용자가 할 일만 쓴다. 사과·감탄·"AI가" 같은 표현을 쓰지 않는다. 버튼은 동사로 끝낸다.

- 내 차례: "카카오뱅크 앱에서 간편인증을 승인해 주세요." ("인증 대기 중입니다..." 아님)
- 결과 미확인: "발급됐는지 아직 모르겠어요. 중복 발급을 막으려고 다시 발급하지 않아요."
- 완료: "발급했어요. A상사 메일로 보낸 것도 확인했어요." ("성공적으로 완료되었습니다!" 아님)
- 범위 밖: "신고와 세금 판단은 하지 않아요. 신고에 필요한 증명서는 뗄 수 있어요."
- 버튼: "승인하고 발급", "다시 조회", "브라우저로 가기" ("확인", "다음" 아님)

화면 글은 최소한으로 쓴다. 어느 화면이든 아래를 지킨다.

- 가운데점(·)을 쓰지 않는다. 쉼표나 줄바꿈으로 나눈다(대표 2026-11-23, 전 화면 정리).
- 출처나 설명을 다는 회색 보조 글씨("홈택스 확정", "홈택스가 보냄", "AI 쓰지 않음", "기본값")를 넣지 않는다(대표 2026-11-23).
- 회계 말 대신 쉬운 말을 쓴다: 받을 돈, 낼 돈, [받았어요], [아직 기다려요]. 미수금, 수금 처리는 쓰지 않는다.
- 내부 상태값, 오류 코드, 원문 주소를 내지 않는다.
- 폰 앱에는 "PC 화면을 봐 달라", "PC에서 먼저 해 주세요" 같은 안내를 넣지 않는다. QR 연결 화면만 예외다(대표 2026-11-19).
- 카드 문구는 한두 줄, 단추 글은 두세 낱말. 같은 설명을 되풀이하지 않는다.

### v2.2 제안 (2026-11-24) 여러 건 묶음(ADR-059, 캔버스 승인 전)
- 여러 건 발급에 따로 여는 시작 창은 없다. 파일은 입력창에 이름 한 줄(`canvas` 면, 빼기 단추)로 붙는다(대표 결정 2026-11-24).
- 묶음 카드는 요약 다섯 줄(거래처 수, 작성일, 공급가액, 부가세, 합계)만 보이고 행은 목록에 둔다. 근거: 볼타 대량발행 "발행 요약"(총 건수, 거래처, 총 금액, 공급가액, 세액. https://bolta.io/update-note/bulk-tax-invoice), "같은 내용을 두 번 그리지 않는다".
- 목록은 PC에서 대화 위에 뜨는 앱 안 모달(`scrim` + `surface-overlay` + 그림자, 닫기 단추와 바깥 누르기와 Esc)의 표, 폰에서 높이 고정 시트의 카드 줄이다. 맨 위 숫자 셋(발급할 건, 합계, 확인할 건), 거르기 두 칸(`sx-seg`), 찾기. 나누는 방법은 PC 표는 선, 폰 줄은 면 하나로 통일한다(받을 돈 화면과 같다).
- 표의 값은 모든 행에서 언제나 입력 칸이고 테두리를 그리지 않는다. 누른 칸만 `tint` 면과 커서가 생긴다(대표 지적 2026-11-24). 넣고 빼기는 PC 맨 앞 체크, 폰 좌우 밀기다. 줄마다 빼기 단추를 따로 두지 않는다.
- 확인할 건은 `attention` 점과 짧은 이유를 거래처 옆에 붙이고 맨 위에 모은다. 카드의 주의 면은 하나다("확인할 4건이 있어요").
- 문제는 발급 전에 알리고 빼고 발급한다. 끝 카드는 미리 뺀 건만 다시 보인다(대표 지적 2026-11-24).
- 실패에 빨강을 쓰지 않는다. 끝 카드의 뺀 건은 주의 면 한 줄과 거래처, 이유, 금액 줄이다. 근거: 세모리포트 [국세청 전송 오류] 카드와 건별 [재전송](https://docs.channel.io/semoreport-ceo/ko/articles/세금계산서-발행관리-ad0c5f81).
- 금액 열은 오른쪽 정렬 고정폭 숫자이고 억 단위(1,273,580,000원)가 줄바꿈 없이 들어가는 폭(124)을 준다.
- 단추 줄은 카드, 모달, 시트 어디서나 왼쪽부터 놓고 가장 중요한 단추가 맨 앞이다. 오른쪽 정렬 단추 줄과 머리 줄 오른쪽 조용한 단추를 쓰지 않는다. 여러 건 승인 카드는 [승인하고 발급] [자세히 보기] [중지] 순서이고, 한 건 ApprovalCard(왼쪽 [중지], 오른쪽 [승인하고 발급])도 구현 때 이 순서로 맞춘다(대표 지적 2026-11-24).
- 승인 전 [자세히 보기]는 읽기 전용 상세 모달(PC)과 시트(폰)다. 목록 모달과 같은 틀에서 체크 열만 뺀다.

- 스크롤바는 평소 투명하고, 마우스가 스크롤 영역 위에 있거나 스크롤하는 동안(`is-scrolling`)만 얇게 보인다(`bundle.css` "Scroll"). 터치 기기는 OS 표시를 그대로 쓴다.
- 좌우 스크롤을 만들지 않는다. 목록 표는 상자 안에서 가로로 밀지 않고 값을 줄바꿈한다.
- 서체 절의 보안카드 등록 문장을 SecretField 지침(OS 테두리 창, ADR-025·026)에 맞췄다.

### v1.2 (2026-11-02) · 디자인 갱신 "더 조용하고, 더 적게, 더 분명하게"

2026년 실리콘밸리 AI 제품 UI가 수렴하는 방향(research/R12: 대화 중심 캔버스와 옆 패널, 조용한 무채 면과 강조색 하나, 시스템·가변 서체, 4/8pt 간격, 최소한의 테두리와 은은한 높이, 인라인 상태 표시, 점진 공개, 명령 팔레트, 다크 동등, 절제된 움직임, 접근성 대비)에 맞춰 v1.1의 시각 규칙을 다듬었다. 구조와 보안 규칙은 그대로다.

원칙

- 면은 네 단으로 끝낸다: `canvas` → `surface` → `surface-tint` → `surface-overlay`. 라이트는 바탕과 카드의 차이를 줄이고, 다크는 위로 뜰수록 밝다.
- 테두리는 필요한 곳에만: 카드·표·작은 보조 버튼은 `line`, 입력 칸·주요/보조 버튼은 `line-strong`(3:1), 무채 칩과 오늘 요약·검색 칸은 테두리 없음.
- 굵기는 400·500·600 셋: 700은 서류 이름과 승인 바 동작 글자에만. 한글 라벨에 자간을 넣지 않고, 화면 제목은 18px로 낮춰 값(D1)이 먼저 보이게 한다.
- 간격은 4px 격자에 맞춘다: 카드 안쪽 16, 요소 사이 12, 메시지 사이 16. 반 칸 값(14·18)을 없앴다.
- 모서리는 담는 것은 조금 더(카드 12, 입력창·말풍선 16), 누르는 것은 그대로(버튼 8, 칸 6). 승인 바는 직각.
- 움직임은 상태가 바뀔 때만: 120/160/220ms와 현재 단계 점의 2.4초 숨 쉬기. 동작 줄이기면 모두 끈다.
- 두 테마를 함께 설계하고, 모든 글자 색은 네 면 위에서 4.5:1 이상을 지킨다.

바뀐 것

- `tokens.json`: 더함 `surface-tint`, `line-soft`, `accent-strong`, `scrim`, `shadow-raised`, `space-0`, `control-height-sm`, `motion` 묶음(120/160/220/2400ms, 두 곡선). 값 조정 `canvas`(라이트 #F5F6F7), `surface-sunken`(라이트 #EEF0F2), `line`(라이트 #E4E7EB), `shadow-overlay`(더 가깝고 옅게), `radius-lg` 10→12, `radius-xl` 12→16, `figure-lg` 행간 32→30·자간 -0.015em, `label` 자간 0, `title-screen` 20/28→18/26. 기존 토큰 이름은 모두 남겼다(코드·컴포넌트가 이름으로 읽는다).
- `components/bundle.css`: 버튼 4단 위계와 hover·누름, 무채 칩 테두리 제거, 말풍선 `surface-overlay`·테두리 없음, 입력창 `radius-xl`+`shadow-raised`·원형 보내기 버튼, 오늘 요약 상자 → 한 줄, 레일 선택 `surface-tint`, 패널 간격 16/12, 현재 단계 점 숨 쉬기, 색 변화 전환.
- 컴포넌트 지침: ApprovalBar(시각만), Button, StatusChip, Message, Composer, TaskCard, KeyValue, StepList, MainScreen, ChoiceCard, Identifier, DocumentCard, Amount에 "모양(v1.2)" 줄을 더했다.
- `direction-review.html`: v1.2 토큰과 컴포넌트를 브라우저에서 바로 보는 미리보기(라이트·다크 전환, 승인 바 세 상태 포함)로 고쳤다. 2026-10-30의 방향 3안 비교는 결정 기록으로 접어 두었다.
- PoC 셸(`poc/apps/desktop/static/shell/shell.css`, 승인 바 내장 CSS `approval-gate.ts` `barCss`): 같은 토큰을 적용했다. 승인 바는 라벨 굵기·불투명도, 표시 칩 모서리, 동작 글자 자간만 바뀌었고 치수는 같다.

바뀌지 않은 것

- 보안 규칙 전부(ADR-021): 승인 바는 main이 소유하는 대화 열 하단·입력창 위의 띠이고, 카드 안에 승인 버튼이 없으며, 무장 지연 0.6초·머무름 0.15초, 세 정적 페이지 교체(애니메이션 없음), 직각·그림자 없음, 시스템 서체, 커스텀 커서 금지, 키보드 승인 없음, 요약 줄은 사용자가 확인해야 할 값(공급받는자 상호·사업자번호, 합계·세액, 받는 이메일) 그대로. 바 안의 치수(높이 90, 라벨 76, 동작 132, 간격 12 DIP)와 레이아웃 치수(`titlebar-height`·`rail-width`·`panel-width`·`chat-max`, 입력창 예약 110, 간격 12)도 같다.
- 한국어 문구 전부(문구 원칙, 상태 이름, 버튼 글자, 안내 문장).
- 데이터 위계 D1~D6과 값의 확실성 5단계, 표기 형식, 배치 순서(`data-hierarchy.md`).
- 색의 두 가지 뜻(파랑 한 색 = 차례·승인, 황토 = 확인 필요), 완료·실패에 색 없음, 서체 세 벌.
