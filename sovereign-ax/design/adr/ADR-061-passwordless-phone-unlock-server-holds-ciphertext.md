# ADR-061. 비밀번호 없는 계정: 폰 생체로 PC 잠금 풀기, 서버는 암호문만, 공동인증서 비밀번호 유출 경로 차단

> 상태: 승인(2026-11-24 대표 "응 그렇게해.", 개정 1 포함, 화면 캔버스도 함께). 대표 지시(2026-11-24 yulmu): "비밀번호는 삭제하고, 이미 연결된 모바일에서 faceid 혹은 지문인식으로 pc의 잠금을 해제할 수 있도록. 우리 서버에서 비밀번호를 탈취해서 사용자의 계정에 접근 가능한 루트를 완전 차단하자. 또한 공동인증서 비밀번호를 우리가 다루다보니, 이 비밀번호를 어떻게든 빼내려고 하는 루트도 최대한 차단할 수 있도록 해."

## 한눈에

| 지금 | 바꾼 뒤 |
|---|---|
| 이메일 코드 또는 이메일과 비밀번호로 로그인 | 비밀번호가 없다. 이메일 코드는 "누구 계정인지"만 알린다 |
| 서버가 계정 열쇠를 맡아 두고, 로그인한 새 PC에 내준다 | 서버는 계정 열쇠를 갖지 않는다. 새 PC는 쓰던 폰이 생체 확인 뒤 직접 넘겨준다 |
| PC 앱은 켜면 바로 열리고, 금고도 OS 로그인만 되면 조용히 열린다 | PC 앱은 잠긴 채 켜지고, 그 PC의 생체인식(Touch ID, Windows Hello)이나 연결된 폰의 Face ID, 지문으로 연다 |
| 공동인증서 비밀번호를 본체 화면에서 받고, 맥에서는 키체인의 보통 항목으로 풀린다 | 금고 전용 창이나 폰에서만 받고, 사람 확인(PC 생체, 폰 생체, 이메일 숫자, 복구 코드) 없이는 디스크에서 풀리지 않는다 |

원칙 하나로 줄이면 이렇다. **서버가 가진 것만으로는 어떤 열쇠도 열리지 않는다. 열쇠를 푸는 힘은 사용자 기기(폰 보안칩, PC 금고, 종이에 적은 복구 코드)에만 있다.**

## 맥락: 지금 뚫리는 길(코드 확인, main b2bc67b)

### 서버 쪽

- **S1. 서버가 모든 계정 열쇠를 열 수 있다.** `key_escrow` 표의 봉인문은 환경변수 `KEY_ESCROW_KEY`로 열린다(`services/account`, 마이그레이션 010). DB와 환경변수가 함께 새면 모든 계정의 RK가 나온다. RK가 있으면 AIK로 기기 목록에 자기 기기를 넣고, 계정 공유 기록(발급 기록, 거래처, 받을 돈 요약)을 읽는다.
- **S2. 서버는 세션을 스스로 만들 수 있다.** 이메일 코드도 비밀번호도 서버가 확인한다. 서버를 장악한 사람은 아무 계정의 세션을 만들어 `POST /v1/key-escrow/claim`으로 RK를 받는다(`remote-account.ts` `#joinByEscrow`). 로그인 수단을 아무리 강하게 해도 이 길은 남는다.
- **S3. 서버가 열쇠를 바꿔치기하면 PC가 따라간다.** `POST /v1/key-escrow/reset` 뒤 다른 PC는 `account.key_changed`로 로그인 화면에 가고, 이메일 로그인 한 번으로 새 열쇠를 받아 자기 장부의 줄을 새 열쇠로 다시 올린다(`share.resend`). 서버가 고른 열쇠로 기록을 다시 올리게 만들 수 있다.
- **S4. 비밀번호 평문이 로그인 때마다 서버를 지난다.** 저장은 argon2id와 페퍼지만(ADR-038), 처리 코드를 바꾸면 평문을 모을 수 있다. 다른 서비스와 같은 비밀번호를 쓰는 사용자가 위험하다. 재설정은 메일 코드 하나다.

### PC 쪽(공동인증서 비밀번호)

- **C1. 맥에서는 풀 열쇠가 키체인의 보통 항목이다.** `keychainBackend()`가 맥에서 `DevKeychainWrapper`를 쓴다(`packages/vault/src/keychain/backend.ts`). 슬롯 KEK를 감싸는 키가 `wrapkey/dev` 항목에 그대로 있다. 같은 사용자 권한으로 키체인을 읽으면 인증서 비밀번호까지 풀린다. 등급 이름도 `keychain-dev`다.
- **C2. 금고는 사람 확인 없이 열린다.** `SessionLock`은 앱을 켤 때와 OS 잠금을 풀 때 `silent = true`로 연다. Hello 사본은 두 플랫폼 모두 `UnavailableHello`라 실제로는 없다. 즉 PC 로그인만 되어 있으면 금고는 조용히 열린다.
- **C3. 인증서 비밀번호를 본체 화면에서 받는다.** `shell-app.ts`의 `openSecret`이 본체 렌더러에 입력 칸을 띄우고, 값은 JS 문자열로 IPC를 지나 main에서 바이트로 바뀐다(`answerSecret`, `saveCertMemory`). 렌더러 힙, IPC, main 힙에 지울 수 없는 문자열 사본이 남는다. 은행 연결(CODEF)은 이미 금고 전용 창(`secret-window.ts`)을 쓴다.
- **C4. 윈도우는 네이티브 헬퍼가 없어 저장이 거부된다.** `WindowsNativeWrapper`의 헬퍼가 `null`이라 `vault.native_helper_missing`으로 끝난다. 안전하지만 매번 묻는다.
- **C5. CODEF 공개키를 우리 서버가 준다.** 게이트웨이 `POST /v1/codef/token` 응답의 `publicKey`로 인증서 비밀번호를 RSA 봉인한다(`codef-seal.ts`). 봉인문은 PC에서 CODEF로 바로 가므로 서버가 키를 바꿔도 지금은 읽지 못하지만, 서버가 준 키를 믿을 이유가 없다.
- 이미 막혀 있는 것: 값 없는 로그(이벤트 이름만), 누출 스캐너, 금고가 Chrome 파이프를 혼자 가짐, 입력 대상 주소 고정(`SECRET_ORIGINS.cert_password = hometax.go.kr`, 금고 상수), 디버그 스위치 거부(`harden.ts`), 퓨즈 확인(`package-win.mjs`), 업데이트는 앱에 고정한 Ed25519 키와 투명성 기록으로 검증(`packages/updater`), 틀린 비밀번호는 바로 지움.

## 결정

### 1. 비밀번호를 없앤다

- 로그인 화면에서 비밀번호 칸, [비밀번호 찾기], 가입 뒤 "비밀번호 만들기" 권유를 뺀다. 설정의 비밀번호 만들기와 바꾸기도 뺀다.
- 서버 경로를 지운다: `POST /v1/auth/password`, `/v1/auth/password/reset`, `/v1/auth/password/reset/verify`, `PUT /v1/password`, `DELETE /v1/password`. 비밀번호 해시, 솔트, 잠금 횟수 열을 마이그레이션으로 지우고 페퍼 환경변수를 없앤다.
- PC 코드: `passwordLogin`, `setPassword`, `skipPassword`, `startReset`, `finishReset`(`remote-account.ts`)과 `CLOUD_ROUTES`의 해당 줄을 지운다.
- 남는 로그인 수단은 이메일 6자리 코드(와 이미 있는 패스키)다. 이 둘은 계정 세션만 준다. 계정 세션으로 할 수 있는 일은 결제, 동의, 기기 목록 보기, 긴급 정지뿐이고 **열쇠를 여는 일은 하나도 없다**(결정 2).
- 옛 판 앱이 비밀번호 경로를 부르면 서버는 `request.not_found`로 답한다. 옛 판에서도 이메일 코드 로그인은 그대로 된다.

### 2. 서버는 계정 열쇠를 갖지 않는다

- `key_escrow` 표와 `KEY_ESCROW_KEY`, 경로 `GET/PUT /v1/key-escrow`, `/claim`, `/pub`, `/reset`을 없앤다(옮겨 가기는 결정 10). 서명한 기기 목록을 받는 `/join`은 `POST /v1/devices/join`으로 이름을 바꿔 남긴다(서버는 계정에 고정된 AIK로 서명만 검사한다).
- **기기는 고정한 AIK를 조용히 바꾸지 않는다.** PC와 폰은 처음 받은 `AIK_pub`를 고정한다. 서버가 다른 AIK를 내밀면(`account.key_changed`) 로그인 화면으로 보내지 않고 "계정 열쇠가 바뀌었다는 알림이 왔어요. 내가 한 일이 아니면 그대로 두세요"를 보인다. 새 열쇠를 받는 길은 그 기기에서 사람이 직접 고르는 [이 기기를 새로 연결]뿐이다. 장부의 줄을 새 열쇠로 다시 올리는 일(`share.resend`)도 그 뒤에만 한다. S3을 닫는다.
- 서버에 남는 것: 이메일, 세션과 갱신 토큰의 해시, 기기 등록부, `AIK_pub`, AIK 서명 기기 목록, 계정 공유 기록 암호문, (사용자가 만들었다면) 복구 코드로 잠근 열쇠 암호문(결정 8), 결제 정보.

### 3. 폰이 풀기 열쇠(Ux)를 갖는다

- 새 키 `Ux`: 폰 보안칩 안의 P-256 키. 키 합의(ECDH)에만 쓰고, 쓸 때마다 생체를 확인한다. 승인 서명 키 `Px`(ADR-052)와 따로 둔다(용도 분리).
  - iPhone: Secure Enclave, 접근 제어 `privateKeyUsage + biometryCurrentSet`, `WhenPasscodeSetThisDeviceOnly`. 폰 암호로는 열리지 않는다. 생체를 다시 등록하면 키가 무효가 되고 PC와 한 번 다시 맞춘다.
  - Android: 키스토어(StrongBox, 없으면 TEE), `setUserAuthenticationRequired(true)`, `BIOMETRIC_STRONG`, 생체 등록이 바뀌면 무효. 칩 안에서 ECDH를 못 하는 OS 판이면 칩 안 AES 키(생체마다 열림)로 감싼 키를 쓴다. 어느 쪽인지는 구현 때 실기기로 확인하고 `hw`에 적는다.
  - 계산은 네이티브 모듈(`modules/sax-native`) 안에서 끝낸다. 풀린 값은 JS로 올라오지 않는다.
- 등록은 `Px`와 같은 길이다: 폰이 라이브 세션에서 `ux.enroll {uxPub, hw, sig(Vm)}`을 보내고 PC가 받는다(자동 등록, 대표 결정 2026-11-19와 같은 원칙). PC는 그 폰 기록에 `ux{pub, hw, enrolledAt}`을 적는다. 폰이 3대면 3대 모두 등록된다.
- `Ux`로 여는 것은 두 가지다.
  - **PC 잠금 열쇠**(결정 5): PC가 자기 디스크에 둔 봉인문을 여는 조각.
  - **계정 열쇠 사본**(결정 4): PC 금고가 RK를 `Ux` 공개키로 봉인해 폰에 넘겨 둔 것(`RKw`). 폰 저장소에 암호문으로 있고 생체 없이는 풀리지 않는다. 서버에는 올리지 않는다.
- 금고 연산을 더한다(control 포트, main만): `rkSealToPhone(uxPub, phoneDeviceId)`. AIK 서명 기기 목록에 있는 폰에게만 봉인하고, 하루 3번 상한과 `vault.rk_sealed`를 그대로 쓴다.

### 4. 새 PC는 쓰던 폰이 연결해 준다

두 PC를 같이 켤 필요가 없다는 ADR-050의 장점은 그대로 두고, 서버 대신 폰이 열쇠를 건넨다.

1. 새 PC: 이메일 코드로 로그인한다(계정 세션). 연결 신청(`POST /v1/devices/enroll`, 지금 있는 것)을 하고, 금고가 넘겨받기 키 `Hx`를 만든다. 화면에 QR을 띄운다: `{deviceId, HxPub, s}`. `s`는 16바이트 무작위 값이고 서버에 보내지 않는다.
2. 폰: 앱의 [PC 추가]로 QR을 찍는다. "새 PC를 내 계정에 연결할까요?"에 생체로 답한다.
3. 폰 네이티브 모듈: `Ux`로 `RKw`를 열고, 바로 `HxPub`로 다시 봉인한다(HPKE, info `SAX-pclink-rk-v1`, aad `SHA-256("SAX-phone-join-v1" ‖ AIK_pub ‖ deviceId ‖ HxPub ‖ phoneDeviceId)`). 여기에 `tag = HMAC-SHA256(HKDF(s, "SAX-phone-join-v1"), AIK_pub ‖ deviceId ‖ HxPub ‖ enc ‖ ct)`를 붙여 연결 우편함(`/v1/pc-links`, 지금 있는 것)에 올린다.
4. 새 PC: `tag`를 `s`로 검사한다. 맞으면 폰이 알려 준 `AIK_pub`가 진짜다(QR은 화면에서 폰으로 바로 갔고 서버는 `s`를 모른다). 서버가 말한 `AIK_pub`와 다르면 멈추고 알린다. 금고 `rkImport`는 연 열쇠의 AIK가 그 값과 같을 때만 받는다(지금 있는 검사).
5. 새 PC가 자기를 더한 기기 목록을 AIK로 서명해 올린다(`POST /v1/devices/join`). 모든 기기에 알림과 메일이 간다. 화면에는 6자리 입력이 없다.

- 공동인증서와 인증서 비밀번호는 지금처럼 새 PC에서 다시 등록한다. 금고 자료는 기기 밖으로 나가지 않는다.
- 새 PC에서 같은 QR로 폰과의 직접 통로(폰 연결)도 함께 맺는다. 사용자는 QR을 한 번만 찍는다.
- 폰이 없으면 결정 7의 길로 간다.

### 5. PC 잠금: 그 PC의 생체인식이 먼저, 폰으로도 연다

- **잠금 열쇠(LK)**: PC마다 금고가 만드는 32바이트 무작위 값. 사람 비밀(공동인증서 비밀번호, 홈택스 비밀번호, 은행 연결용 비밀번호)의 슬롯 KEK를 LK로 한 번 감싸고, 그 위를 기기 결박 키로 한 번 더 감싼다. 디스크만 가져가도, 폰만 가져가도 풀리지 않는다.
- 지금의 조용한 기기 사본(`kek/<slot>/device`만으로 풀리는 길)은 없앤다. C1, C2를 닫는다.
- **LK 사본**은 PC 디스크에 봉인문으로만 있다.
  - 폰 사본(폰마다 하나): `HPKE(UxPub, LK)`, DHKEM(P-256, HKDF-SHA256), info `SAX-unlock-v1`, aad `SHA-256(pcDeviceId ‖ phoneDeviceId ‖ AIK_pub)`.
  - 이 PC 사본(생체인식이 되는 PC): 맥은 Touch ID로만 열리는 키체인 항목(`biometryCurrentSet`, 이 기기 전용, 동기화 안 함. 지문을 새로 등록하면 항목이 죽고 폰으로 한 번 열어 다시 만든다), 윈도우는 Windows Hello(지금 있는 `HelloProvider` 자리). 맥 로그인 암호로는 열리지 않는다. 생체인식이 없는 PC(센서 없음, 등록 안 함, 맥북 덮개 닫음)에는 이 사본을 만들지 않고 폰으로만 연다. 설정에서 끌 수 있다.
  - 이메일 사본(결정 7): 서버가 가진 조각과 이 PC의 기기 결박이 함께 있어야 풀린다.
  - 복구 코드 사본(결정 7): `AEAD(HKDF(RK, "SAX-lock-recovery-v1" ‖ pcDeviceId), LK)`. RK 자체는 잠기면 LK 아래에 있으므로, 복구 코드로 서버의 `RKr`을 열어 RK를 얻어야 풀린다.
  - 서버 혼자 풀 수 있는 사본은 없다.
- **잠기는 때**: 앱을 켰을 때, OS 화면 잠금과 잠자기와 사용자 전환, 15분 동안 손대지 않았을 때, 열린 지 8시간(`VAULT_IDLE_LOCK_SEC`, `VAULT_UNLOCK_MAX_SEC` 그대로). OS 잠금을 풀어도 금고는 조용히 다시 열리지 않는다(ADR-026 결정 3을 고친다).
- **잠기면**: 본체 창은 잠금 화면만 보인다(장부와 대화가 보이지 않는다). 금고는 슬롯 KEK와 LK를 지운다. 기기 키(통신, 서명)와 계정 갱신 토큰은 무인 등급으로 남아서, 잠긴 PC도 폰의 풀기 답과 맡긴 일을 받을 수 있다. 계정 갱신 토큰을 무인 등급으로 옮기는 까닭은 계정 세션이 더는 열쇠를 열지 않기 때문이다(결정 1, 2).
- **잠금 화면**: 생체인식이 되는 PC는 뜨자마자 Touch ID나 Windows Hello를 묻고, [Touch ID로 열기](윈도우는 [Windows Hello로 열기])와 [폰으로 열기]를 함께 보인다. 폰에는 [폰으로 열기]를 눌렀을 때만 보낸다. 생체인식이 안 되는 PC는 바로 폰에 보내고 기다린다. 어느 화면에나 [다른 방법](이메일, 복구 코드)이 있다.
- **폰으로 푸는 순서**
  1. PC 잠금 화면이 뜨면 금고가 한 번용 키 `Tx`(X25519)와 난수 `n`을 만들고, 그 폰의 봉인문에서 `E`(임시 공개키)를 꺼내 `unlock.request {reqId, pcDeviceId, E, TxPub, n, exp(60초), scope}`를 만든다. main이 폰과의 종단간 통로(Noise)로 보내고, 통로가 닫혀 있으면 내용 없는 푸시로 깨운다(ADR-053, 종류 `unlock` 추가).
  2. 폰: 통로의 상대가 연결할 때 고정한 그 PC인지 보고, "○○ PC 잠금을 풀까요?"를 띄운다. 생체가 통과하면 보안칩에서 `Z = ECDH(Ux, E)`를 계산해 `TxPub`로 봉인해 돌려준다(`unlock.grant`, aad `SHA-256(reqId ‖ n ‖ pcDeviceId ‖ phoneDeviceId ‖ E)`).
  3. 금고: `Tx`로 열어 `Z`에서 LK를 꺼낸다. 열리면 `Tx`를 지우고, 모든 폰 사본을 새 임시 키로 다시 봉인한다(가로챈 `Z`는 다음에 쓸 수 없다).
- 릴레이와 서버는 Noise 암호문만 본다. 서버는 풀기 요청을 지어낼 수도, 답을 읽을 수도 없다.
- 폰이 [아니요]를 누르면 PC는 5분 동안 다시 묻지 않고 양쪽에 "잠금 풀기를 거절했어요"를 남긴다. 풀기 요청은 10분에 3번까지다(졸라서 누르게 하는 공격을 줄인다).
- 엄격 모드(ADR-026 결정 4)는 설정 > 잠금의 여는 기기 스위치로 바꾼다(이 PC 생체인식, 폰마다, 이메일로 열기를 따로 끈다).

### 6. PC가 잠겨 있어도 폰에서 맡긴 일은 돈다

- 폰이 일을 맡길 때 PC가 잠겨 있으면, 맡기는 그 자리에서 생체를 한 번 확인하고 `scope: "remote"` 풀기를 함께 보낸다.
- `remote` 풀기는 금고만 연다. 본체 화면은 잠긴 그대로다. 그 폰이 맡긴 일에만 쓰이고, 마지막 일이 끝나고 10분 뒤 또는 PC에서 누가 [잠그기]를 누르면 닫힌다.
- 발급 승인은 지금처럼 `Px` 서명으로 따로 받는다(ADR-052). 풀기는 "PC 금고를 써도 된다"이고 승인은 "이 내용으로 발급한다"라 뜻이 다르다. PC가 열려 있으면 생체는 승인 한 번뿐이고, 잠겨 있으면 맡길 때 한 번이 더해진다. 여러 건을 이어서 맡기면 풀기는 처음 한 번이다.

### 7. 폰을 쓸 수 없을 때: 이메일 숫자나 복구 코드

생체인식도 폰도 쓸 수 없는 때(폰을 두고 옴, 배터리 없음, 폰을 연결하지 않음, 생체인식 없는 PC)를 위한 길이다. 우리 서비스의 비밀번호는 어디에도 없다.

- **이메일로 열기(이미 쓰던 PC만)**
  - PC마다 금고가 32바이트 조각 `Se`를 만들어 서버에 맡기고 자기 쪽에서는 지운다. 디스크에는 `AEAD(HKDF(Se ‖ 기기 결박 키, "SAX-unlock-email-v1"), LK)`만 남는다.
  - 잠금 화면에서 [이메일로 열기]를 누르면 서버가 계정 이메일로 숫자 6자리를 보낸다. 숫자가 맞고 요청에 그 PC의 기기 키 서명이 있으면 서버가 `Se`를 그 PC의 `Q_D`로 봉인해 준다. 금고는 풀고 나서 `Se`를 새로 만들어 다시 맡긴다.
  - 서버가 통째로 털려도 `Se`만으로는 아무것도 못 연다. 봉인문은 그 PC 디스크에 있고 기기 결박 키가 함께 있어야 한다. 반대로 PC 디스크만 가져간 사람은 `Se`가 없다.
  - 숫자는 5번 틀리면 1시간 막고, 하루 5번까지 보낸다. 이메일로 열면 연결된 폰과 이메일에 "이메일로 PC를 열었어요"가 간다. 설정에서 끌 수 있다.
  - 새 PC는 이 길로 계정 열쇠를 받지 못한다. 이메일만으로 열쇠를 주면 서버가 계정에 들어오는 길(S1, S2)이 되살아난다.
- **복구 코드로 열기**: 금고 창에 복구 코드를 넣는다. 금고가 서버의 `RKr`을 받아 코드로 RK를 열고, RK로 복구 코드 사본에서 LK를 꺼낸다. 쓰던 PC의 잠금도, 새 PC 연결도 이 코드 하나로 된다.
- **폰 없는 사용자의 새 PC**: 이메일 숫자로 로그인한 뒤, 쓰던 PC가 켜져 있으면 6자리 승인(ADR-048 결정 3, 지금 있는 것), 아니면 복구 코드.
- **생체인식도 폰도 없는 PC**: 열 때마다 이메일 숫자나 복구 코드를 쓴다. 조용히 열리는 길은 두지 않는다.

### 8. 분실과 복구: 서버 혼자서는 되살리지 못한다

| 상황 | 길 | 필요한 것 |
|---|---|---|
| 폰을 잃어버림, PC는 있음 | PC 설정 > 기기 연결에서 그 폰을 끊는다. 바로 폐기되고 그 폰의 LK 사본과 `ux` 기록을 지운다. 새 폰은 QR로 연결한다 | 로그인된 PC |
| 폰을 잃어버림, 다른 폰이 있음 | 다른 폰에서 잃어버린 폰을 정지한다(지금 있는 `stop`). PC에서 확정한다 | 연결된 다른 폰 |
| PC를 바꿈, 폰은 있음 | 결정 4 | 폰과 생체 |
| PC를 바꿈, 폰 없음, 쓰던 PC 켤 수 있음 | 6자리 승인 | 쓰던 PC |
| PC도 폰도 없음, 복구 코드 있음 | 새 PC에서 이메일 숫자 뒤 복구 코드를 넣는다 | 적어 둔 복구 코드 |
| 아무것도 없음 | 되살릴 수 없다. 지금 있는 탈퇴(`account.deleteRequest`, 유예 중 취소 가능) 뒤 같은 이메일로 다시 가입한다 | 이메일 |

- **훔친 폰으로는 못 연다.** `Ux`는 생체 전용이라 폰 암호를 알아도 풀기와 PC 추가가 안 된다. 폰 앱도 들어갈 때 생체를 본다.
- **복구 코드(첫 PC를 설정할 때 만든다)**: 첫 PC 설정의 마지막에 금고 창이 120비트 무작위 값을 4글자씩 여섯 묶음으로 한 번 보여 주고 [다 적었어요]를 받는다. 금고는 `RKr = AEAD(HKDF(code, salt, "SAX-recovery-v1"), RK)`를 만들어 서버에 올린다. 서버가 가진 것은 암호문이고, 120비트 무작위 값이라 서버 자료로 맞혀 볼 수 없다. 설정 > 잠금 > [다시 만들기]로 바꾸면 옛 코드는 못 쓴다. 코드는 금고 창에서만 보이고 저장하지 않는다. 틀린 입력은 PC에서 5번에 1시간 막는다.
- **새로 시작은 두지 않는다(개정 1).** 이메일만으로 계정에 새 열쇠를 거는 길은 이메일을 훔친 사람이 옛 기기를 끊으려 드는 길이기도 해서 7일 유예와 취소 알림 같은 장치가 따라붙는다. 복구 코드를 처음부터 만들게 했으므로 그 길 없이도 막히는 사람이 드물다. 다 잃은 계정은 탈퇴 뒤 다시 가입하고, 발급한 세금계산서는 홈택스에 그대로 있다.

### 9. 공동인증서 비밀번호: 길마다 막는다

| 길 | 지금 | 바꿈 |
|---|---|---|
| 디스크 | 맥은 보통 키체인 항목으로 풀림(C1) | LK(폰 조각)와 기기 결박 두 겹(결정 5). `DevKeychainWrapper`는 개발 실행에서만 쓰고, 패키지된 앱이 `keychain-dev` 등급이면 저장을 거부한다 |
| 금고 열림 | OS 로그인만으로 조용히(C2) | 이 PC 생체, 폰 생체, 이메일 숫자, 복구 코드 뒤에만. 잠기면 KEK와 LK를 지움 |
| 입력 | 본체 렌더러, JS 문자열, IPC(C3) | 금고 전용 입력 창(`openVaultInputWindow`, `SECRET_CSP`, 화면 캡처 제외)에서 받아 MessagePort로 금고에 바로 보낸다. main과 본체 렌더러는 값을 보지 못한다. `answerSecret`의 `cert_password` 길과 `saveCertMemory`를 지운다. 또는 폰에서 넣는다(폰이 금고 키 `Kv`로 봉인, D05 §5, 큐에 넣지 않음) |
| IPC | 렌더러가 문자열을 보냄 | 본체 IPC 채널 목록에 비밀 값을 받는 채널이 없게 하고, 시험이 채널 목록을 고정한다 |
| 쓰는 순간 | 금고가 CDP로 홈택스 칸에 입력, 주소는 금고 상수 | 그대로. 인증서 창이 다른 주소로 바뀌면 입력을 멈추는 지금 검사를 유지한다 |
| 메모리 | 잠기면 KEK를 0으로 덮음. CDP JSON에 문자열 사본이 남음(D05 §8) | 그대로 두고 잔여 위험에 적는다. 금고를 Electron 밖으로 빼는 일(D05 Phase 2)이 근본 해법이다 |
| 로그 | 이벤트 이름만, 누출 스캐너 | 새 입력 길에 카나리아 시험을 더한다: 정한 값이 로그, 본체 IPC, 렌더러 DOM, 덤프 폴더에 0건 |
| 확장, 디버그 | 전용 Chrome 프로필과 확장 허용 목록, 앱 디버그 스위치 거부, 퓨즈 | 맥 패키징에도 같은 퓨즈 확인을 넣는다(지금 스크립트는 `package-win.mjs`) |
| 업데이트 공급망 | 고정 Ed25519 키, 투명성 기록, 되돌리기 방지, 릴리스 키는 서버에 없음 | 그대로. 서버가 털려도 앱을 바꿔치기하지 못한다 |
| 우리 서버 | 인증서 비밀번호는 서버로 가지 않는다 | 그대로. 대화(모델 호출)에는 비밀이 들어가지 않는다(ADR-019) |
| CODEF | 서버가 준 공개키로 봉인(C5) | CODEF 공개키 지문을 앱에 고정하고, 게이트웨이가 준 키가 다르면 거부한다 |
| 폰 | 폰은 인증서 비밀번호를 저장하지 않는다 | 그대로. 폰이 갖는 것은 풀기 조각이고, 그것만으로는 아무것도 열리지 않는다 |
| 틀린 값 | 한 번 틀리면 기억값을 지움 | 그대로(인증서 잠김 방지) |
| 윈도우(C4) | 저장 거부 | 폰 사본이 있으면 저장을 연다(LK 봉인문은 자격 증명 관리자, 풀기는 폰). TPM, DPAPI, Hello 헬퍼가 들어오면 기기 결박과 이 PC 사본을 더한다 |

### 10. 옮겨 가기

다른 기기가 같은 때 켜져 있다고 가정하지 않는다(K-21, K-30).

1. **1단계(앱과 서버 같은 커밋)**: 비밀번호 경로와 화면을 지운다. 폰 `Ux`, PC 잠금, 폰으로 새 PC 연결, 금고 입력 창을 넣는다. 서버의 맡긴 열쇠는 아직 지우지 않는다.
2. **계정마다 스스로 옮긴다**: 새 판 PC가 켜지면 연결된 폰에 `RKw`를 넘기고(폰이 새 판이 된 다음 세션에서 자동), 서버에 "이 계정의 맡긴 열쇠를 지워라"를 AIK 서명으로 보낸다. 폰이 없는 계정은 복구 코드를 권하고, 만들거나 [나중에]를 고르면 지운다.
3. **기한**: 1단계 게시 30일 뒤 남은 `key_escrow` 줄을 모두 지우고 `KEY_ESCROW_KEY`를 없앤다. 그때까지 새 판을 한 번도 켜지 않은 계정의 새 PC는 6자리 승인으로 간다. 기한 전에는 옛 길(`claim`)이 열려 있으므로 "서버가 열쇠를 못 연다"는 말은 기한 뒤부터 쓴다.
4. **2단계(열쇠 바꾸기)**: 옛 열쇠는 서버가 열 수 있던 값이다. 새 판 PC가 새 RK를 만들어 옛 AIK로 교체에 서명하고(`SAX-aik-rotate-v1`), 기기 목록에 있는 다른 PC의 봉투 키(`Q_D`)로 봉인해 서버 우편함에 둔다. 다른 PC는 다음에 켤 때 받는다. 폰은 다음 세션에서 새 `RKw`를 받는다. 공유 기록은 세대를 올려 다시 봉인한다. 옛 백업이 새더라도 그 뒤 기록은 열리지 않는다.
5. 운영 DB 마이그레이션은 PR이 main에 합쳐진 뒤에, 게이트웨이와 PC 앱은 같은 커밋으로.

## 잔여 위험(숨기지 않는다)

- **PC가 열려 있는 동안 같은 사용자 권한의 악성코드**는 금고에 일을 시킬 수 있다(D05 §1 "금고는 오라클"). 이 설계는 잠긴 시간과 디스크에 대해서 막는다.
- **침해된 main**은 풀기 요청을 폰에 보낼 수 있다. 폰 화면의 확인과 거절 뒤 5분 멈춤, 10분 3번 상한이 방어다.
- **대화 내용은 게이트웨이를 지난다.** 서버가 털리면 그 기간의 대화(거래처 이름, 금액이 들어 있을 수 있다)가 보인다. 비밀은 대화에 들어가지 않는다.
- **Android는 키 증명 검증기가 아직 없다**(ADR-052). 풀기 키가 정말 보안칩에 있는지 PC가 확인하지 못한다. 발급 승인은 지금처럼 Android에서 받지 않고, 풀기만 받는다. 검증기가 들어오면 `hw`를 확인한다.
- **Windows Hello는 생체가 실패하면 PIN을 받는다.** 윈도우가 정한 동작이라 앱이 막지 못한다. PIN을 아는 사람이 PC 앞에서 열 수 있다. 설정에서 이 PC 생체인식을 끄면 닫힌다.
- **이메일로 열기**는 PC를 손에 넣고 그 사람의 메일함까지 볼 수 있는 사람(PC에 메일이 로그인돼 있는 경우 포함)에게 열린다. 서버만 턴 사람에게는 열리지 않는다. 폰과 이메일에 알림이 가고, 설정에서 끌 수 있다.
- **다 잃으면 되살릴 수 없다.** PC, 폰, 복구 코드가 모두 없으면 앱의 기록은 끝이다. 서버 혼자 되살리는 길을 두지 않은 값이다.
- **폰 네이티브 모듈 안에서 RK가 잠깐 평문이 된다**(결정 4의 다시 봉인). JS로는 올라오지 않고 바로 덮는다.
- **CODEF를 켠 계좌**는 조회하는 동안 인증서와 비밀번호가 CODEF에 간다(ADR-044의 좁은 예외, connectedId는 조회마다 지움). 이 설계가 바꾸지 않는다.
- **홈택스 인증서 창에 값이 들어간 뒤**는 그 페이지와 보안 모듈의 영역이다.
- 관리자, 커널 권한 공격자는 범위 밖이다(D05 §1).

## 기각

- **비밀번호를 더 강하게(OPAQUE, 2단계 인증)**: 서버가 세션을 만들 수 있는 한 S2가 남는다. 문제는 로그인 수단이 아니라 "세션이 열쇠를 여는 것"이었다.
- **PC 잠금을 서버가 확인하는 폰 승인으로(푸시 승인 뒤 서버가 토큰 발급)**: 서버가 털리면 풀린다. 디스크의 암호문도 그대로 풀린다.
- **폰이 서명만 하고 PC가 그 서명을 보고 열기**: 열쇠가 PC에 다 있으므로 PC 디스크를 가진 사람은 서명 없이 푼다. 그래서 서명이 아니라 열쇠 조각을 폰이 가진다.
- **풀기 조각을 폰 키체인 항목으로 보관**: 생체 뒤 값이 통째로 앱 메모리에 올라온다. 보안칩 키 합의는 PC가 보낸 그 봉인문 하나만 연다.
- **서버에 암호문을 두고 폰이 풀 열쇠를 갖기(PC 잠금)**: 서버를 거칠 이유가 없다. 봉인문은 PC 디스크에 두면 된다.
- **새 PC 연결에 6자리 입력**: QR에 실은 비밀 값(`s`)으로 폰의 답을 검사하면 사람이 숫자를 옮길 필요가 없다.
- **맥 로그인 암호로 열기**: 대표 지시(개정 1)로 뺐다. 생체인식이 안 되면 폰이다.
- **이메일 숫자만으로 새 PC에 열쇠 주기**: 서버가 숫자를 확인하므로 서버를 턴 사람이 계정에 들어온다. 이메일은 이미 열쇠가 있는 PC의 잠금에만 쓴다.
- **새로 시작(이메일만으로 새 열쇠 걸기)**: 결정 8.

## 화면(캔버스에 먼저 그린다)

- PC: 잠금 화면(생체인식 먼저와 [폰으로 열기], 폰 기다림, 거절됨, 폰이 안 닿음, 다른 방법, 이메일 숫자), 로그인(이메일과 숫자만), 새 PC 연결 QR과 [폰이 없어요], 설정 > 잠금(이 PC, 폰 목록, 이메일로 열기, 복구 코드), 금고 창(인증서 비밀번호, 복구 코드 보여 주기와 넣기).
- 폰: 잠금 풀기 요청, PC 추가(찍기와 확인), PC가 잠겨 있을 때 맡기기, 설정의 PC 풀기.

## 구현 기록

- **1~3단계 PC 쪽(2026-11-24)**: 슬롯 KEK는 `kek/<slot>/lk` 하나(LK와 기기 결박 두 겹), CODEF 비밀번호도 같다. 옛 `device`, `hello` 사본과 `settings/strict`는 처음 열릴 때 옮기고 지운다. 계정 갱신 토큰은 잠금과 상관없이 기기 결박만으로 둔다.
- **첫 사본**: LK를 처음 만든 PC에 다른 사본(이 PC 생체인식, 폰, 이메일, 복구 코드)이 하나도 없으면 다시 켤 때 열 길이 없어 LK가 사라진다. 그래서 다른 사본이 생길 때까지만 기기 결박으로 풀리는 첫 사본(`lk/device`)을 두고, 그동안은 잠그지 않는다. 사본이 생기면 바로 지운다. 결정 7의 "조용히 열리는 길은 두지 않는다"는 사본이 하나라도 생긴 PC에 대한 것이다. 생체인식이 되는 맥은 첫 실행에 Touch ID 사본이 생겨 첫 사본이 남지 않는다.
- **맥 Touch ID**: 키체인 항목 대신 보안칩 키 합의 키(CryptoKit `SecureEnclave.P256.KeyAgreement`, `privateKeyUsage + biometryCurrentSet`, `WhenUnlockedThisDeviceOnly`)로 LK를 봉인한다. 폰 사본과 같은 모양(보안칩이 Z만 내준다)이고, 보안칩 키는 서명이나 키체인 권한 없이 만들 수 있어 개발 실행에서도 같다. Swift 도우미(`poc/packages/vault/native/mac`)를 금고 프로세스가 부른다. 도우미는 앱 묶음(`Resources/touchid.app`, Info.plist 이름 택스오프와 아이콘)으로 싣는다(2026-11-26). 맨 실행 파일이면 시스템 Touch ID 창 제목이 "touchid", 아이콘이 exec로 떴다. 보안칩 키는 키를 쓰는 프로세스의 LAContext로만 풀리므로 Electron `systemPreferences.promptTouchID`(앱 프로세스에서 예/아니오만 묻기)로 옮기지 않는다. 그러면 LK가 생체에 묶이지 않는다. 잠금 화면은 메인 창이 보일 때 바로 묻고(숨은 창 뒤에서 띄우지 않음), 취소하면 [Touch ID로 열기] 단추로 다시 연다. 창이 숨었다 다시 보이면 또 묻는다.
- **사본을 묶는 신원**: LK 메타에 이 PC의 계정 기기 번호와 AIK 공개키를 처음 연결할 때 고정한다. 다른 값이 오면(이 PC를 새로 연결) 옛 신원에 묶인 폰, 이메일, 복구 코드 사본을 지운다.
